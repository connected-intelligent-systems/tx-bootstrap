# Release 0.2.1

This patch fixes S3 secret references in the participant portal.

## Changes

- **Secret reference** field for S3 asset creation and editing, with English
  and German guidance for existing provider-side secret aliases.
- Secret references appear in the asset's **Data Address** tab and survive
  edits to asset metadata.
- Directly entered S3 secret keys are masked in the form.
- Regression coverage for reference preservation and existing direct credentials.

Update the participant portal frontend to use these changes. Existing secret
aliases remain valid; the form references secrets already provisioned in the
provider's configured secret store.

See [S3 HTTP-pull configuration](../s3-http-pull.md) for setup and usage.
