# Release 0.4.1

This release fixes two problems that kept participants on the operator tunnel
unreachable. Packages, images, Compose artifacts, and Helm charts share
version `0.4.1`.

## Fixes

- **Tunnel routes disappeared after a few minutes.** The operator console's
  request rate limit (100 requests per 15 minutes per client address) also
  applied to `/api/network/tunnel-routes`. The ingress polls it every five
  seconds and publishes no routes when a request fails, so after about eight
  minutes no tunnelled participant was reachable. The endpoint is now exempt
  from the limit; requests without the routing token are still rejected.
- **Tunnelled Compose participants never obtained a certificate.** In the
  `tx-bootstrap-participant-tunnel` package, the public gateway also used the
  participant's public host name as an alias on the `public` network. The TLS
  endpoint connects to that name to detect that the ingress routes it, reached
  its own gateway instead, and kept waiting. The gateway now keeps only its
  role-scoped aliases on that network, and the tunnel sidecars reach it as
  `<role>-public`. `TAILNET_FORWARD_HOST` still overrides this. Helm
  deployments were not affected.

## Upgrade

Select matching `0.4.1` images and deployment artifacts. No database
migrations and no configuration changes.

**Operators:** update the operator console. Workarounds that disabled its rate
limit can be removed.

**Tunnelled Compose participants:** update to the `0.4.1` tunnel package. A
participant waiting with `Waiting until the operator's ingress routes <host>
to this node` requests its certificate once the new gateway aliases apply.
Do not give any container on the participant's `public` network the public
host name as an alias.
