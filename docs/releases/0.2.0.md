# Release 0.2.0

This release adds optional S3 sources over authenticated HTTP-pull and updates
application and runtime dependencies. The six application images, two Compose
applications and two charts use the synchronized version `0.2.0`.

## Changes

- Optional data-plane image with native S3 → `HttpData-PULL` support, standard
  EDR authorization and token refresh.
- `EDC_DATAPLANE_IMAGE` selects the optional image in participant deployments;
  the local startup script builds its `local` tag when selected.
- Patched application dependencies and a rebuilt, pinned `0.12.2` data-plane
  runtime with serializer security updates and upgraded OS packages.
- Public gateway DNS refresh after data-plane container recreation.
- Artifact publication and regression checks for unresolved templates.

See [S3 HTTP-pull configuration](../s3-http-pull.md) for image selection, source
addresses and provider-side storage credentials.

## External-network migration

Reusable Compose applications now use literal network-ownership booleans so
their unresolved templates can be published. Deployments that previously used
`OPERATOR_EDGE_NETWORK_EXTERNAL=true` or
`PARTICIPANT_PUBLIC_NETWORK_EXTERNAL=true` against the reusable base manifests
must add an explicit deployment override.

For an operator:

```yaml
networks:
  edge:
    external: true
```

For a participant:

```yaml
networks:
  public:
    external: true
```

The local deployment overlays retain those environment flags and default to
external shared networks. Network names remain configurable through
`OPERATOR_EDGE_NETWORK` and `PARTICIPANT_PUBLIC_NETWORK`.

Only S3 source → `HttpData-PULL` is validated for the optional image. Other
advertised transfer combinations require separate verification.
