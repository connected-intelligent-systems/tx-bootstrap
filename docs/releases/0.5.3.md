# Release 0.5.3

This release lets the Compose gateways follow recreated services and makes the
local Kubernetes setup follow Rancher Desktop's ingress address. Packages,
images, Compose artifacts, and Helm charts share version `0.5.3`.

## Fixes

- **Compose gateways kept forwarding to the old address of a recreated
  service.** nginx resolved upstream host names only at startup. After an
  update recreated the control plane, Identity Hub, issuer service, or BDRS,
  the participant gateways and the operator's `issuer-did` proxy still used the
  old container address, and their health check failed while an upstream was
  absent. They now resolve upstreams at runtime through Docker DNS. The Helm
  charts are unaffected: Kubernetes services keep stable addresses.

## Local development stack

- The local Kubernetes scripts read the ingress address from Rancher Desktop's
  Traefik service instead of assuming `192.168.64.7`, and keep it for the
  installation in `.generated/ingress-ip`. `LOCAL_K8S_INGRESS_IP` still
  overrides it.
- The local end-to-end test moves the provider control plane to a new address
  before its catalog request, without restarting the gateways.
- `verify.sh` checks that participants reach each other and the issuer inside
  the cluster. When Rancher Desktop has changed its VM address, it names the
  old and new address.

## Known issues

- Helm operators installed with a chart before 0.4.0 created their credential
  status list with the internal `issuer-did` service address. Credentials
  issued from that list fail their revocation check outside the operator
  namespace, and participants refuse each other's catalog requests with 401.
  Later charts configure the public address, but an existing status list keeps
  the old one. Such installations need a new issuer state and reissued
  credentials.
- EDC-based services occasionally start without serving their health
  endpoints: `/api/check/readiness` answers 404 and the container stays
  unhealthy until it is restarted. The local `up.sh` restarts it once; Compose
  deployments need a manual restart. Unlike stated for 0.5.2, Helm deployments
  recover by themselves: their startup and liveness probes use these endpoints,
  so Kubernetes restarts the pod.
- The transfer race after new agreements and the deprecated Management API v3
  calls remain as described for [0.5.2](0.5.2.md#known-issues).

## Upgrade

Select matching `0.5.3` images and deployment artifacts. No database
migrations.

**Compose participants and operators:** Compose does not recreate services when
only their inline configuration changes. Recreate the gateways once after this
update; later updates need no gateway restarts:

```sh
# participants
docker compose up -d --force-recreate internal-gateway public-gateway
# operators
docker compose up -d --force-recreate issuer-did
```

**Local Kubernetes stacks** installed with the former default address keep
working only while Rancher Desktop uses `192.168.64.7`. Set
`LOCAL_K8S_INGRESS_IP=192.168.64.7` in a custom environment file to keep such
an installation, or reinstall with `down.sh --volumes` and `up.sh`.
