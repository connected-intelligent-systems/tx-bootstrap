# Release 0.5.2

This release fixes route refreshes on the tunnel ingress and a transfer race
after new agreements, and moves the local Compose stack to Vault 2.0.2.
Packages, images, Compose artifacts, and Helm charts share version `0.5.2`.

## Fixes

- **The tunnel ingress could block all participants on hosts with slow DNS
  search domains.** The ingress node accepted Tailscale DNS, which replaced
  Docker's resolver settings for the tunnel router in its network namespace.
  The router's lookup of the console name then tried the host's search domains
  first; when they answered slowly, every route refresh timed out and the
  ingress blocked new connections ("Tunnel route refresh failed"). The ingress
  node now keeps Docker DNS. The router does not need MagicDNS: the console's
  routes carry node addresses.
- **Data access could fail right after a new agreement.** Tractus-X EDC 0.13.0
  stores an agreement's BPNs asynchronously after the negotiation finalizes.
  A transfer requested before that is refused permanently with
  `No BPN entry found for agreement`, although a new transfer on the same
  agreement succeeds. The participant portal now starts such a transfer once
  more after two seconds, and the local end-to-end test retries it once.
- **Participant connectors use the `edc.iam.trustedissuer` configuration
  prefix.** Tractus-X EDC 0.13.0 deprecated `edc.iam.trusted-issuer`. BDRS keeps
  the old prefix.

## Local development stack

- Vault 2.0.2 replaces 1.15, the same version as the local Kubernetes setup.
  The Vault containers start as root so the unseal wrapper can read its key
  file; the server itself still runs as `vault`.
- `bootstrap.sh` runs again on a stack that is already set up.
- `up.sh` restarts a service once when its readiness check answers 404, and
  the Vault bootstrap fails after 180 seconds (`VAULT_WAIT_SECONDS`) instead of
  waiting forever.
- Unused portal translations are removed.

## Known issues

- EDC-based services occasionally start without serving their health
  endpoints: the runtime logs that it is ready, but `/api/check/readiness`
  answers 404 and the container stays unhealthy. Restarting the container
  resolves it. The local `up.sh` does this once by itself; Compose and Helm
  deployments need a manual restart.
- The transfer race after new agreements is an upstream issue (see
  eclipse-tractusx/tractusx-edc#2915). Clients other than the portal that start
  a transfer immediately after a negotiation should retry this refusal once.
- Tractus-X EDC 0.13.0 logs every Management API v3 call as deprecated. The
  portal moves to v4 once the Tractus-X EDR and agreement retirement endpoints
  are available there.

## Upgrade

Select matching `0.5.2` images and deployment artifacts. No database
migrations.

**Operators with the tunnel ingress:** update the `0.5.2` tunnel artifact and
recreate `tunnel-node` and `tunnel-router`. The node keeps its identity.

**Compose and Helm participants:** update to `0.5.2`. If you set the trusted
issuer for the control plane yourself, rename `EDC_IAM_TRUSTED-ISSUER_*` to
`EDC_IAM_TRUSTEDISSUER_*`.

**Local Compose stacks:** the first start upgrades the existing Vault data to
2.0.2. Vault cannot be downgraded afterwards; to return to an older checkout,
reset the stack with `down.sh -v`.
