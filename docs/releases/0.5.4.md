# Release 0.5.4

This release makes partner catalogs recover quickly after short outages, lets
users refresh them from the portal, and fixes onboarding a BPN again after its
participant was revoked. Packages, images, Compose artifacts, and Helm charts
share version `0.5.4`.

## Fixes

- **A failed partner catalog stayed failed for 15 minutes or longer.** After a
  failed crawl the federated catalog waited the full refresh interval, then
  twice as long after each further failure. A partner that was briefly
  offline, or the own connector still starting after a restart, kept the error
  in the portal long after it was resolved. The first retry now comes after
  `CATALOG_RETRY_SECONDS` (60); repeated failures back off as before, up to an
  hour.
- **A BPN onboarded again got no credentials.** The Issuer Service cannot
  delete holders: revoking a participant blocks its holder, and a participant
  that moves to another DID keeps its holder with the old one. When the same
  BPN was approved again, for example an external BPN, a revoked participant
  onboarded anew, or a participant moving to the tunnel, the setup kept that
  holder, and the issuer refused the participant's credential requests. The
  setup now updates the holder to the approved DID, as it already did for the
  BDRS entry. Credentials revoked for an earlier participant stay revoked.

## Features

- The portal's **Discover data** page has a **Refresh partner catalogs**
  button. It crawls all partners now and waits for the results. The retry
  button in the catalog warning does the same; before, it only reloaded the
  page and showed the old error again.
- The federated catalog has `POST /v1/refresh` and
  `POST /v1/participants/{bpn}/refresh`, available to API clients through the
  participant API with the `federated-catalog:read` scope. A partner refreshed
  in the last 30 seconds is skipped.

## Known issues

- The issues listed for [0.5.3](0.5.3.md#known-issues) remain.

## Upgrade

Select matching `0.5.4` images and deployment artifacts. No database
migrations and no configuration changes.
